大家好，這是封閉測試的第16篇

由於距離第14篇已經過了一將近一個月，所以，我改以"篇"來稱呼。

這期間，因為這與第15篇一樣，都是原本PWA做不到的，因為若要主動通知使用者，就必須能操作原生系統。

由於鬧鐘我是設定每當使用者打開這APP，就會自動去設定未來一天內的鬧鐘，這也意味著，如果使用者設了很多鬧鐘，然後有隔很久才打開APP，就會一次需要設定多個鬧鐘，所以，只好使用 postMessage 的方式。

但是，Android TWA對 postMessage的支援頗難設置的，所以才花了這麼長的時間在調教。

現在，我們就進入實際操作的部分。

首先，打開這個APP，然後點 More，再重播這個鬧鐘設定的操作教學。

所以，要設定鬧鐘，請先到 Scheduled 頁面。因為，只有排程項目們才可以設定鬧鐘。

接著點 "Show More" ，然後請勾選第一個，第二個若您想嘗試再試，AI說了一堆例外情況，礙於開發時間壓力，暫時先不處理那些例外情況。

然後，請點 "確定"。這樣才確定設置了。這樣，每個排程項目就可以設 "提醒偏移" 了。

為了立即看到效果，請按 "新增"，好新增一筆排程項目，然後設定提醒偏移，5m,-15m，這樣就會設兩個鬧鐘。

想像這是一個希望壓縮在15分鐘內完成的重要會議，一個在5分鐘前響好提醒，一個在15分鐘後響，強制準備開始做結論，免得拖延時間。

而這偏移是根據 "下次執行" 的時間來計算的。所以，我們選比現在晚七分鐘的時間吧。

按 "保存"。這樣，重新開啟這個APP，就會自動設定他。

不過，我們也可以強制他立刻更新鬧鐘。

請按 "查看鬧鐘"。再按 "更新鬧鐘序列"，這樣就會立刻更新所有的鬧鐘。

如果他寫 set ，那就是已經設了，若是寫 pending，則很可能不在一天之內要發生，系統鬧鐘不會因重開機而被破壞，但另一個則會，所以，才建議另一個若您不放心，可以不打勾，因為怕您會收不到第二個的提醒，因為很可能被系統丟掉了。請記得，這只是暫時的解決方案，未來可能會有更完善的處理方式。

這就是我們設定的鬧鐘。
