# Scheduled

## 目的

1. 特定の時点で実行する必要があるタスクを記録し、その時点でユーザーに通知します。
2. これは一度きりのタスクでも、定期的なタスクでも構いません。さらに、あるタスクが完了した後、一定時間経過後にユーザーに別のタスクへの切り替えを通知するように設定することもでき、アクティビティチェーンを形成することも可能です。
例えば、洗濯をした後、しばらくしてユーザーに洗濯物を干すように通知する、といった具合です。
3. 他のカレンダーシステムから ics ファイルをインポートします。インポート後、システムは自動的に解析し、対応するタスクを追加します。
4. カレンダーや月間ビューを使用して、スケジュールされたタスクを確認および管理します。
5. タスクを ics ファイルに変換し、他のアプリケーションと共有することもでき、クロスプラットフォームでの管理が容易になります。
6. プライベート情報の共有を避けるため、タスクを他のアプリケーションと共有する前に、所属するプロジェクトを設定する必要があります。
7. Android アプリでは、アラームを設定してユーザーに事前にタスクを通知することができます。

## 使用方式

1. 追加：
   1. `+Add` をクリックして新しいタスクを追加します。
   2. iPhone では、`ショートカット` の `NBL Scheduled` をコントロールセンターに配置できます。これにより、iPhone の右上から下にスワイプするだけで、ショートカットをタップして新しい Scheduled タスクを素早く追加できます（iPhone のカレンダーにもエントリが追加されます）。
2. 削除：（削除は推奨されません。統計データを保持するために、Done に変更することをお勧めします）
   1. 各レコードには `Delete` ボタンがあり、またはスマートフォンで左にスワイプして削除することもできます。
3. 編集：
    1. スマートフォンの場合、項目を右にスワイプして編集画面に入り、変更後に `保存` を押します。
    2. コンピュータの場合、変更後にフォーカスが外れると更新が完了します。
    3. プロジェクト ID の部分で、タスクを分類できます。この ID は ics をエクスポートする際に必須です。各 ics は特定のプロジェクトに対応している必要があり、すべてをエクスポートすると情報漏洩の可能性があります。
    4. Android アプリで `アラームオフセット` を設定している場合、システムは `NextRun` の時間の前にユーザーに事前通知します。
    5. `回呼動作` を設定することで、あるタスクが完了した後に別のタスクを自動的にトリガーし、アクティビティチェーンを形成できます。現在は、同じく Scheduled タスクにのみ設定可能です。
4. `Candidates` に表示されるタイミング：
   1. 一度きりのタスク：設定した時点で `Candidates` に表示され、ユーザーに実行を通知します。
   2. 定期的なタスク：各定期的な時間に `Candidates` に表示され、ユーザーに実行を通知します。
   3. アクティビティチェーンのタスク：最初のタスクが完了し、一定時間経過後に `Candidates` に表示され、ユーザーに実行を通知します。
5. 開始と終了：
   1. `Candidates` からタスクを選択して開始します。終了も `Candidates` で行い、その後 `Log` に記録されます。
   2. 終了時、一度きりのタスクであれば Done に設定されます。

## 重要なフィールドの説明

1. `Title`: タスクのタイトル。簡潔で明確であることが推奨されます。
2. `Status`: `NextRun` によって決定されます。ただし、`Status==Done` の場合は考慮されません。
3. `ProjectID`: タスクが所属するプロジェクトの ID。タスクを分類するために使用され、ics をエクスポートする際の情報セキュリティを確保します。
4. `Cron`: **重要**
   1. 定期タスクの設定。形式は `* * * * *` で、それぞれ `分 時 日 月 曜日` を表します。`*` を使用して任意の値を表すことができ、またはカンマで複数の値を区切ったり、ハイフンで範囲を示したり、スラッシュでステップを示すこともできます。詳細な使用方法は Google で Crontab を検索してください。一度きりのタスクの場合は `null` です。
   2. 現在、2 つの追加拡張構文がサポートされています：
      1. `rN`（相対ステップ、5 つのフィールドのいずれかに使用可能）
         1. 意味は「現在の計算時の `baseDate` を起点として、N 単位ごとに 1 回実行」。
         2. 例えば、月フィールドに `r3` を入力し、現在が 5 月の場合、`5,8,11` に展開されます。ユーザーが 9 月まで完了しなかった場合、次回は 9 月以降から計算され `9,12` となります。
         3. この設計は「見逃した後に現在のリズムから再開する」タスクに適しています。
      2. `every` / `@every`（全体の相対間隔）
         1. `every 30m`、`@every 2h`、または `3d`、`1w`、`1M` を直接使用できます。
         2. 次回実行時間 = `baseDate + 間隔` を意味し、純粋な間隔リマインダーに適しています。
   2. `Candidates` で Scheduled タスクを終了すると、そのタスクの `Cron` が `null` でない場合、次回の `NextRun` が自動的に計算され、データベースに更新されます。これにより、定期的なタスクが形成されます。
5. `アラームオフセット`：事前または事後の通知時間を設定します。デフォルトの単位は分です。
6. `事前通知`: `NextRun` の時間の前に、何分前にユーザーに通知するかを設定します。これにより、通知を見逃すことがありません。
7. `事後通知`: `Candidates` でタスクを終了した後、何分後にユーザーに通知するかを設定します。別のタスクの開始に連動して、アクティビティチェーンを形成することもあります。
8. `回呼動作`: アクティビティチェーンの対象タスクで、`title` によって対応します。
9. `備註`: タスクの備考。詳細やタスク完了後の感想などを記録できます。
10. `NextRun`: 次回実行の時間。これは `Cron` によって計算されるか、一度きりのタスクの設定時間です。`Candidates` では `NextRun` の時間に基づいて、このタスクを表示するかどうかが決まります。
